# Phase 5 — Measurements and decisions

วันที่วัด: 2026-10-07 · ค่าต่ำสุดทั้งหมดตามที่สั่ง: Claude `claude-haiku-4-5-20251001` effort `low`, Codex รุ่นเริ่มต้น effort `low`

## ที่ทำ

- **ปิดช่องว่างของ GUI** (PR แยก): dependency และ check ต่องานในฟอร์ม, review/continue ด้วยได้ทั้งสอง agent, ตาราง usage, token/ราคาต่อ attempt
- **Quota-aware routing** (PR แยก): agent `auto` ไปที่ agent แรกที่ login/ไม่ cooling/มี slot ว่าง และย้ายเมื่อชน quota — รายละเอียดอยู่ใน [ROADMAP](ROADMAP.md)
- **ทดลองวัด Debate ก่อนสร้าง** (เอกสารนี้): ไม่สร้างระบบ debate ใด ๆ

## การทดลอง Debate (`probes/debate.py`)

คำถาม: ให้ "เสนอแผน → อีก agent วิจารณ์แผน → เขียนตามแผนและคำวิจารณ์" ดีกว่า "เขียนตรง ๆ" ไหม บนงานที่ spec มีกฎละเอียดหลายข้อ (benchmark Phase 3 ง่ายเกินไป: ทุก config ได้เต็ม)
วิธี: 3 งาน (semver precedence 7 กฎ, word-wrap 6 กฎ, TTL+LRU cache) × 2 เงื่อนไข × 2 รอบ ตัดสินด้วย hidden tests บน commit สุดท้าย (ตรวจแล้วว่า reference ผ่านครบ และ stub ที่ไม่ทำอะไรล้มหมด: `--selftest`)

## ข้อสรุปและขอบเขต

1. **สัญญาณเดียวที่เห็นอยู่ที่ semver:** direct ล้ม 2 จาก 2 รอบที่ตรวจ version ผิดรูป (กฎ 6) ส่วน debate ผ่านเต็ม 1 รอบ (อีกรอบค้าง) งานอื่นไม่มีความต่าง (ทั้งสองผ่าน) นั่นคือ **อาจ**มีประโยชน์เฉพาะ spec ที่มีรายการกฎตรวจ/ข้อผิดพลาดยาว แต่หลักฐานคือ 1 งาน ต่างกัน 1 เซลล์ ไม่ควรสรุปเป็นอื่น
2. **ราคาจริง:** ~3 เท่าของเวลาและ token ในทุกงาน รวมงานที่ direct ผ่านอยู่แล้ว
3. **ความเสี่ยงของวิธี:** 2 จาก 6 รอบของ debate ค้างที่ `REVIEW` ในขั้นแผนจึงไม่ได้ผล (สาเหตุที่แน่ชัดผมไม่ได้เก็บไว้ — ข้อมูลของรอบนั้นถูกลบแล้ว; เดาว่าแผนแตะไฟล์นอก scope `notes/` แต่ยังไม่ยืนยัน) งานต่อกันที่ขั้นแรกค้างรอคน จะค้างทั้งสาย สคริปต์ผมรอเต็ม 15 นาทีต่อเซลล์ก่อนแก้ให้หยุดทันที
4. ตัวอย่างเล็ก (3 งาน × 2 รอบ), โมเดลเดียวคู่เดียว, ค่าต่ำสุด; ไม่มีค่าความแปรปรวน
5. **คำแนะนำ:** ยังไม่สร้างระบบ Team/Debate (OD-017 ยังไม่ต้องตัดสินใจ) ถ้าอยากลอง ใช้มือสร้างสามงานต่อกันด้วย `--after` กับ spec ที่เต็มไปด้วยกฎตรวจสอบเท่านั้น และรู้ว่าจ่ายราว 3 เท่า การวัดที่น่าเชื่อถือกว่านี้ต้องมีหลายรอบและงานที่ล้มจริงเป็นประจำ (เช่นงานจริงของ VELA) ซึ่งตอนนี้ยังไม่มี

## ที่ไม่ได้ทำ

A2A bridge, desktop wrapper, adversarial review เป็นของเฉพาะทาง ไม่มี use case บันทึกไว้ (ตามที่คุณเลือกให้ตัด) คุณภาพ routing เทียบแบบสองทางยังไม่มีหลักฐาน
